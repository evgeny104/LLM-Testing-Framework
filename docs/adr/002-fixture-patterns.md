# ADR-002: Два паттерна фикстур — фабрики и константы

## Статус
Принято.

## Контекст
pytest-фикстуры можно определять в файле теста, в conftest.py или
строить фабриками. Нужно единое правило, чтобы проект читался одинаково.

## Решение
Два паттерна, выбор — по числу кейсов:

1. **Много кейсов** (уровень 1): golden dataset (`golden_cases.py`)
   + фабрика `make_model_answer(CASES)` (`test_fixtures/llm_fixtures.py`).
   Параметризованная фикстура: один вызов модели на кейс (scope=module),
   тесты не дублируются.
2. **Один сценарий** (уровни 4–7): константы QUESTION/SYSTEM_PROMPT
   прямо в файле теста, вызов `complete()` в теле теста. Читается
   сверху вниз, никакой магии.

## Последствия
+ Правило простое: «много кейсов → датасет, один сценарий → константы».
+ Уровень 1 расширяется строкой в golden dataset.
− Два паттерна вместо одного — новичку нужно одно правило (оно выше).

## Альтернативы
Фабрики везде — отвергнуты: лишняя абстракция для одиночных сценариев.
Только константы везде — отвергнуты: дублирование фикстуры
в каждом файле уровня 1 при параметризации по CASES.
