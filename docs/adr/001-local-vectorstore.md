# ADR-001: Локальная векторная БД вместо API-эмбеддингов

## Статус
Принято.

## Контекст
Для RAG-уровней нужен поиск по базе знаний. Стандарт индустрии —
эмбеддинги через API (OpenAI/Groq) и vector store (pgvector, Qdrant).
Проект учебный, тариф Groq бесплатный: каждая индексация и поиск
эмбеддингами расходует токены и добавляет сетевую зависимость.

## Решение
Локальная векторизация без внешних API (`vectorstore/store.py`):
hashing-векторизация токенов + символьные n-граммы (3–5) с весами IDF,
поиск — косинусная близость (numpy). Данные — txt-файлы в
`vectorstore/knowledge_base/`, одна статья = один файл.

## Последствия
+ Ноль токенов на индексацию и поиск; ноль сетевых зависимостей.
+ Добавление документа = положить txt-файл, код не меняется.
− Качество ниже эмбеддингов на больших корпусах; на 5 статьях разница
  незаметна, на тысячах — критична.
→ Интерфейс `VectorStore.search()` позволяет заменить `_vectorize()` на
  вызов эмбеддингов без правки ни одного теста.

## Альтернативы
API-эмбеддинги (Groq) — отвергнуты: стоимость на бесплатном тарифе,
сложность локальной разработки офлайн.
Простой keyword-поиск без векторов — отвергнут: не масштабируется на
морфологию («товар»/«товара») без ручного стемминга.
